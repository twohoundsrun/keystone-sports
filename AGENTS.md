# Keystone Beat — Agent Notes

Keystone Beat is an independent Pennsylvania sports desk (scores, schedules, team
hubs, standings, odds, news wire) plus an owner-gated editorial system ("Beat
desk"). It is **standalone**: no Grok preview host, no Grok subscription, no
`/workspace` sandbox contract. It runs as a **Cloudflare module Worker** with a
**D1** database, built with TanStack Start + React 19 + Vite.

Read this file before changing code. Keep it in sync when commands, ports,
secrets, or deploy targets change.

---

## Commands (main app, repo root)

```bash
npm ci                 # install (uses package-lock.json; do not hand-edit deps)
npm run dev            # Vite dev server on 0.0.0.0:8080
npm run build          # production build -> dist/  (vite.standalone.config.ts + scripts/stage-standalone.mjs)
npm run typecheck      # tsc --noEmit
npm run lint           # eslint .
npm run format         # prettier --write .
npm test               # node --test tests/*.test.mjs
npm run beat:seed      # seed Beat data (scripts/beat-seed.mjs)
npm run beat:discover  # discover Beat candidates (scripts/beat-discover.mjs)
```

`npm test` and `npm run test:sports` are currently the **same command**
(`tests/*.test.mjs`); both run in CI.

## Commands (jobs worker, `workers/keystone-beat-jobs`)

```bash
npm ci
npm test               # node --test tests/*.test.ts
npm run typecheck
npm run dev            # wrangler dev
npm run deploy         # wrangler deploy  (do NOT run without approval)
```

CI: `.github/workflows/ci.yml` runs lint → `npm test` → `npm run test:sports` →
build → typecheck for the main app, and tests + typecheck for the jobs worker,
on Node 22. Both jobs must stay green.

## Architecture

- **Routes** are file-based under `src/routes/` (TanStack Start). `src/routeTree.gen.ts`
  is **generated** — never edit it by hand; it is regenerated by the Vite plugin on
  dev/build. Routes can be plain pages or server endpoints whose `loader` returns a
  `Response` with `component: () => null` (see `src/routes/api/auto-recap.tsx`).
- **Request middleware** is registered once in `src/start.ts`:
  `publishedPostsMiddleware`, `apiMiddleware`, `publisherMiddleware`,
  `beatAdminMiddleware`. Cross-cutting API handling (ingest hardening, auto-recap,
  canonical-host redirects) lives in `src/lib/api-middleware.ts`.
- **Runtime data** uses raw D1 prepared statements via
  `src/lib/publishing/runtime.server.ts`. **Drizzle** (`db/schema.ts`, `drizzle/`)
  is used for the schema and migrations only, not the query runtime.
- **Sports feeds** live in `src/lib/sports/` (ESPN + MLB StatsAPI + RSS, with a
  two-tier cache and per-source timeouts/retries).
- **Feed discovery**: the desk defaults to retained RSS/Atom feeds, a cross-isolate ten-minute cooldown, and at most nine requests/ten pending inserts per run. Apply `0005_beat_discovery_state` before use. Last-run source/coverage evidence is owner-only; it does not prove a missing event. Legacy X remains explicit `mode: "legacy_x"`; scheduled Apify stays disabled.
- **Beat** logic is in `src/lib/beat/` (ingest, mutate, ordering, flag) with the
  scheduled discovery/expire work in `workers/keystone-beat-jobs/`.

## Builds & deployment — two targets from one build

`npm run build` uses **`vite.standalone.config.ts`** (nitro preset
`cloudflare-module`) and produces:

- `dist/server/index.mjs` — the **Cloudflare Worker entry** referenced by
  `wrangler.toml` (`main = "dist/server/index.mjs"`).
- `dist/client/` — static assets (`[assets] directory` in `wrangler.toml`).
- `dist/.openai/` — `.openai/hosting.json` + a copy of `drizzle/`.

`scripts/stage-standalone.mjs` additionally writes `dist/server/index.js` (a thin
re-export wrapper of `index.mjs`) for the **OpenAI hosting** target, and now
asserts that `dist/server/index.mjs` exists so a build fails loudly instead of
deploying a broken entry. Keep the wrapper and **both** deploy targets.

`vite.config.ts` is the **local dev/preview** config (nitro preset `vercel`,
`cloudflare:workers` aliased to `src/lib/publishing/cloudflare-workers-dev.ts`);
it is **not** the production build. Do not "fix" one config to match the other.

Deploys go through `wrangler` for the main site and separately for the jobs
worker. **Do not deploy, push, or open a PR without the owner's approval.**

## Secrets (set with `wrangler secret put` — never commit values)

`AI_API_KEY`, `KEYSTONE_AUTO_RECAP_SECRET`, `KEYSTONE_BEAT_INGEST_SECRET`,
`KEYSTONE_JOBS_SECRET`, and `APIFY_TOKEN` (only when re-enabling Apify). Non-secret
vars (`KEYSTONE_ADMIN_EMAIL`, `KEYSTONE_AI_ENABLED`, `AI_BASE_URL`, `AI_MODEL`,
`KEYSTONE_BEAT_M1`, `KEYSTONE_APIFY_ENABLED`) live in `[vars]` in the wrangler
files. Never create a `.env` file or commit keys.

## Editorial workflows (owner-gated)

- `/editor` — owner publishing dashboard (drafts/publish/unpublish, AI recap).
- `/editor/beat` — Beat desk (approve/reject/pin/expire/edit context/discover).
- Owner identity is enforced server-side from the Cloudflare Access header
  (`cf-access-authenticated-user-email`) matched to `KEYSTONE_ADMIN_EMAIL`
  (legacy `oai-authenticated-user-*` only as fallback). **Do not weaken this gate.**
- Bot ingest (`/api/editor/beat/ingest`) is **PENDING-only** and header-secret
  authenticated; it never auto-publishes. Preserve that invariant.

## Conventions & guardrails

- TypeScript everywhere; validate untrusted input with `zod` at the boundary.
- Follow existing Prettier/ESLint config; run `npm run lint` and `npm run typecheck`.
- Drizzle migration history is **append-only**: never rewrite applied `.sql`
  migrations or hand-edit snapshots in `drizzle/meta/`. See below.
- `<PreviewHostBridge/>` stays mounted in `src/routes/__root.tsx` (gated by
  `VITE_STANDALONE`); it is a noop outside the Grok preview and is intentionally
  retained for compatibility.
- Do not change production data, Cloudflare settings, secrets, or auth behavior as
  part of routine maintenance.

## Out-of-band migrations & Drizzle snapshots

`drizzle/meta/_journal.json` lists `0003_beat_job_runs` and `0004_beat_fingerprint_unique`,
but `0003_snapshot.json` / `0004_snapshot.json` do not exist. This is **intentional, not a
defect**: both are out-of-band (custom) SQL migrations whose objects are *not* declared in
`db/schema.ts` — the `beat_job_runs` table (owned by the jobs Worker via raw SQL,
`workers/keystone-beat-jobs/src/metrics.ts`) and the partial unique index
`beat_items_duplicate_fingerprint_unique`. Drizzle snapshots are derived *solely* from the
schema files, so no `drizzle-kit`-generated snapshot can represent these objects; writing
placeholder snapshots would be misleading.

Verified against `drizzle-kit` 0.31.10: `drizzle-kit check` passes, `drizzle-kit generate`
is a no-op, forward diffs off the `0002` snapshot are correct, and `drizzle-kit up` does not
backfill the missing snapshots. Runtime `wrangler d1 migrations apply` is unaffected (it
reads the `.sql` files).

Do **not** hand-write `0003`/`0004` snapshots. If either object is ever brought into
`db/schema.ts`, `drizzle-kit generate` will emit duplicate `CREATE TABLE` / index
operations for it — reconcile that first. `tests/drizzle-migrations.test.mjs` pins the
out-of-band allowlist and asserts these objects stay out of `db/schema.ts`.
